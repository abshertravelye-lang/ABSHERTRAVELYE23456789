# تجهيز نظام البريد الإلكتروني الرسمي — ABSHER TRAVEL

أريد منك تجهيز وربط **نظام البريد الإلكتروني الرسمي لمنصة ABSHER TRAVEL** بالكامل داخل المشروع الحالي على Replit.

## بيانات البريد الرسمية

النطاق الرسمي:

**abshertravel.com**

البريد المخصص لإرسال رسائل النظام:

**[noreply@abshertravel.com](mailto:noreply@abshertravel.com)**

يجب استخدام هذا البريد كمرسل رسمي لجميع رسائل النظام الموجهة للعملاء.

---

# 1. استخدام خدمة إرسال بريد احترافية

قم بربط المشروع بخدمة **Resend** من خلال تكامل Replit الرسمي إن كان متاحًا في المشروع.

لا تنشئ نظام SMTP مؤقتًا أو حلًا تجريبيًا.

يجب أن يكون النظام جاهزًا للإنتاج Production.

قم بإعداد النطاق:

**abshertravel.com**

داخل خدمة البريد، ثم استخدم سجلات DNS المطلوبة للتحقق من ملكية النطاق وتفعيل إرسال البريد من:

**[noreply@abshertravel.com](mailto:noreply@abshertravel.com)**

يجب عدم تغيير البريد إلى عنوان تجريبي مثل `resend.dev`.

---

# 2. استخدام Replit Secrets

يجب حفظ جميع مفاتيح API وأسرار خدمة البريد داخل:

**Replit Secrets / Environment Variables**

ولا يجوز بأي شكل:

* وضع API Key داخل Frontend.
* وضع API Key داخل JavaScript للمتصفح.
* وضع API Key داخل Git.
* إظهار API Key في لوحة التحكم.
* كتابة API Key بشكل ثابت داخل الكود.

يجب أن تتم جميع عمليات إرسال البريد من Backend فقط.

---

# 3. نظام تسجيل الدخول بالبريد الإلكتروني OTP

أريد نظام تسجيل دخول **Passwordless Email OTP**.

عندما يضغط العميل:

**تسجيل الدخول**

يظهر حقل:

**البريد الإلكتروني**

ثم زر:

**إرسال رمز الدخول**

يقوم Backend بإنشاء رمز OTP آمن مكون من 6 أرقام وإرساله إلى:

**البريد الذي أدخله العميل**

من:

**[noreply@abshertravel.com](mailto:noreply@abshertravel.com)**

---

# 4. رسالة رمز الدخول

يجب أن تكون رسالة OTP بتصميم احترافي يحمل هوية ABSHER TRAVEL.

تحتوي على:

**ABSHER TRAVEL**

**رمز الدخول الخاص بك**

ثم الرمز بشكل واضح وكبير.

مثال:

**583214**

ثم:

**هذا الرمز صالح لمدة 10 دقائق ويستخدم مرة واحدة فقط.**

ولا يتم إرسال كلمة مرور للعميل.

---

# 5. حماية OTP

يجب تنفيذ نظام أمان حقيقي:

* الرمز صالح لمدة 10 دقائق فقط.
* الرمز يستخدم مرة واحدة فقط.
* تخزين OTP بشكل آمن، وليس كنص مكشوف إذا كان ذلك ممكنًا.
* تحديد عدد محاولات إدخال الرمز.
* تحديد عدد مرات طلب رمز جديد.
* إضافة فترة انتظار بين عمليات إعادة الإرسال.
* إبطال الرمز السابق عند إنشاء رمز جديد.
* منع إساءة استخدام خدمة إرسال البريد.
* تسجيل محاولات تسجيل الدخول المهمة.
* عدم كشف معلومات حساسة عن وجود الحساب أو عدم وجوده.

---

# 6. إنشاء الحساب تلقائيًا

إذا أدخل العميل بريدًا إلكترونيًا غير موجود في قاعدة البيانات:

بعد نجاح التحقق من OTP:

**يتم إنشاء حساب العميل تلقائيًا.**

ولا يتم إنشاء كلمة مرور.

أما إذا كان البريد موجودًا بالفعل:

**يتم تسجيل دخول العميل إلى حسابه الحالي.**

يجب ربط الحساب بنفس قاعدة البيانات الحالية في المشروع.

**ممنوع إنشاء قاعدة بيانات جديدة أو منفصلة.**

**[noreply@abshertravel.com](mailto:noreply@abshertravel.com)**

**مرحبًا بك في ABSHER TRAVEL**

يجب أن يكون البريد بتصميم احترافي ومتجاوب مع الهاتف والكمبيوتر.

* تم إلغاء الطلب.

# 16. اختبار النظام

بعد تنفيذ الربط، قم باختبار كامل:

### اختبار إنشاء حساب جديد

البريد → إرسال OTP → استلام البريد → إدخال الرمز → إنشاء الحساب → إرسال البريد الترحيبي.

### اختبار مستخدم موجود

البريد → OTP → التحقق → تسجيل الدخول إلى الحساب الحالي.

### اختبار إعادة إرسال OTP

التأكد من وجود الحماية والـRate Limit.

### اختبار طلب التأشيرة

إنشاء طلب → التأكد من وصول إشعار البريد.

### اختبار طلب البرنامج السياحي

إنشاء طلب → التأكد من وصول إشعار البريد.

### اختبار تغيير الحالة

تغيير حالة الطلب من Admin Dashboard → التأكد من وصول البريد للعميل.

### اختبار اللغة

حساب عربي → بريد عربي.

حساب إنجليزي → بريد إنجليزي.
